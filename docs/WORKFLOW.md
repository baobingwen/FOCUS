# 🚀 FOCUS 开发协作流程

本文件定义**用户 + Claude Code 合作开发 FOCUS 的标准顺序**与配套约定，经 v0.2.3 实践验证后固化。后续每个功能迭代都按此流程推进。

---

## 流程总览

```
1. Grill 设计 → 2. 文档先行 → 3. 代码改动 → 4. 测试验证 → 5. 汇总发版
```

| 步骤 | 做什么 | 产出 | 验收标准 |
|------|--------|------|----------|
| 1. **Grill 设计** | 用 /grill-me 把点子问细 | 明确的设计决策 | 每个设计点都有答案，无含糊之处 |
| 2. **文档先行** | 先改文档描述新功能 | 更新后的文档 | 用户确认文档无误 |
| 3. **代码改动** | 按文档实现功能 | 实现代码 + 新测试 | 新功能测试通过 |
| 4. **测试验证** | 跑全量测试 | 全绿测试结果 | 无已有用例被破坏 |
| 5. **汇总发版** | 收尾 + 版本号 + tag | 新版本发布 | 按「版本三轨」推进 |

---

## 详细步骤

### 1. Grill 设计

用 `/grill-me` 细化点子，**问一问一**：一次只抛一个设计问题，逐条确认设计决策，把需求想清楚再动手。

- 目的：让需求在落地前暴露冲突，而不是在代码里发现
- 产出：一份逐条确认过的设计决策清单

### 2. 文档先行（关键步骤）

需求确认后，**先改文档，不碰代码**：

| 文档 | 改什么 |
|------|--------|
| `CONTEXT.md` | 领域语言、核心概念定义（如涉及新概念/新状态） |
| `README.md` | 功能描述、使用流程图 |
| `code/ROADMAP.md` | 日常点子 → 确定设计（标记为已确定） |

**用户确认文档无误后，才进入代码阶段。**

> 原理：v0.2.3 开发中发现「先改文档后改代码」让需求冲突在文档阶段就暴露，节省了大量代码返工时间。

### 3. 代码改动

按文档实现，顺序固定为：

```
组件 → 集成 → 测试
```

- **改前先读现有测试**：了解已有测试模式，新测试风格与旧测试一致
- 服务端与客户端的实现细节见各自的 TESTING.md

### 4. 测试验证

- 跑**全量测试**（`code/server && npm test` + `code/client && npm test`）
- 目标：新用例通过 + **无已有用例被破坏**
- 用例数变化同步到 TESTING.md

### 5. 汇总发版

按下方「配套约定」完成收尾：

1. `CHANGELOG.md` — Unreleased → 版本号 + 日期
2. 版本号三轨推进（见下）
3. 提交 + 打 tag

---

## 关键原则

- **文档改到满意才动手写代码** — 需求冲突在文档阶段暴露，避免返工
- **问一问一** — grill 时一次只确认一个设计点，不一次抛多个问题
- **改动前先读现有测试** — 新代码/新测试与既有风格保持一致
- **小而快** — 每个迭代聚焦一个功能，验证完再进下一个

## 配套约定

### 版本号三轨（v0.2.3 起）

三轨独立管理，互不干扰：

| 轨 | 文件 | 用途 | 何时递增 |
|----|------|------|----------|
| 客户端版本 | `code/client/package.json#version` | 前端功能变更 | 改 client 代码时 |
| 服务端版本 | `code/server/package.json#version` | 后端功能变更 | 改 server 代码时 |
| 项目里程碑 | git tag `vX.Y.Z` | 整体发布标记 | 发版时 |

- 运行时版本不依赖 `git describe`；服务端 `/api/version` 返回 server 版本，前端 `__APP_VERSION__` 由 Vite build 注入
- 三者完全独立，互不联动

### 文档同步检查清单

每次功能改动或发版后，按 `docs/INDEX.md` 逐一检查：

**功能相关（必改）**

- [ ] `CONTEXT.md` — 领域语言、Flow 描述
- [ ] `README.md` — 功能列表、使用流程图
- [ ] `code/ROADMAP.md` — 已实现清单、版本头
- [ ] `CLAUDE.md` — 组件/文件描述表

**测试相关**

- [ ] `code/client/TESTING.md` — 文件树、用例计数（前端改动）
- [ ] `code/server/TESTING.md` — 文件树、用例计数（后端改动）

**发版时**

- [ ] `CHANGELOG.md` — Unreleased → 版本号 + 日期
- [ ] `code/client/package.json#version` — 如有前端改动
- [ ] `code/server/package.json#version` — 如有后端改动
- [ ] git tag — 项目里程碑标记

**通常无需改**

- `code/LOCAL_DEPLOY.md`、`code/start-local.bat`、`code/build-client.ps1` — 部署脚本不写版本号
- `docs/adr/*.md` — 架构决策记录，不受普通功能改动影响（**架构变化时反而要新增 ADR**）
