# 0007: 历史记录删除 — 隐藏的管理模式 + 单条硬删除

历史记录一旦保存就永久存在，误记的、不想要的记录无法清理。给历史页加一个**隐藏的管理模式**：正常使用完全无感知，需要时连点 5 下标题进入，删除单条记录。

## Status

**accepted**

## Design

### 定位：管理员功能 = 防误触的隐藏入口

单用户本地工具，无账号体系。「管理员功能」指的不是权限，而是**隔离度**：删除入口在正常状态下不可见，只有主动触发隐藏口令才出现，防止日常操作中误触。

### 进入 / 退出

- **进入**：连续点击 5 下历史页标题「📋 历史记录」（该标题原本无 onClick，无冲突）。每次点击间隔 ≤2s，超时计数器重置，防止翻页乱点误入。
- **反馈**：进入后标题下方出现黄色横幅「管理模式已开启 — 卡片右上角出现删除按钮」+ 右侧「退出管理模式」按钮。
- **退出**：横幅按钮退出；切 Tab 历史页卸载重建，`useState` 状态自然复位（不持久化，每次进页面默认关闭）。

### 服务端 API

| 端点 | 行为 |
|------|------|
| `DELETE /records/:id` | 硬删除单条记录；id 非正整数或不存在 → 404；学习/休息记录都可删（不做 mode 区分） |

- **硬删除**：`DELETE FROM records WHERE id = ?`，`record_tags` 由外键级联自动清理（`foreign_keys = ON` 已开启）。
- 统计（今日概览）从 records 表实时聚合，删除后自动正确，无需额外处理。
- 沿用 subjects/tags 的 delete 惯例：成功返回 JSON body（非 204）。

### 前端交互

- **删除按钮**：管理模式开启时，每张卡片右上角（时长左侧）出现红色「删」按钮；正在编辑中的记录不显示（与编辑态互斥，避免删除/编辑状态冲突）。
- **确认**：`window.confirm('删除这条学习记录？此操作不可恢复')`（与科目/标签删除同一确认模式，零新组件）。
- **删除后**：`recordsApi.remove(id)` 成功后本地 `setRecords` 过滤该条——今日概览、标签筛选、千层饼均由 records prop 派生，自动同步；失败保留记录 + 内联「删除失败: xxx」，不重拉列表。

## Considered Alternatives

- **常态可见删除按钮**：与「管理员功能」的隔离定位冲突，删除入口永远可见，误触风险靠 confirm 兜底。
- **持久开关（localStorage）**：可能忘记关闭导致删除按钮常驻，隔离效果打折。
- **软删除 + 撤销**：需 `deleted_at` 列 + 撤销计时器 + 定期清理，为单用户工具过度设计。
- **批量多选 / 整日清空 / 清空全部**：UI 复杂度显著上升（多选态/全选/双重确认），单条删除已覆盖「误记一条」的主场景，可后续再扩。
- **仅学习记录可删**：休息记录（如误点直接休息产生的）一旦误建就永久残留，与 PATCH「仅学习记录」的约束动机（备注/标签概念仅学习记录有）不同，删除无此约束。

## Consequences

- 服务端：records 路由新增 DELETE 端点 + 测试（成功 / 404 / id 非法）。
- 客户端：`recordsApi.remove`；HistoryPage 连点标题计数器、管理模式横幅、卡片删除按钮、confirm、本地移除、失败内联报错 + 测试。
- 无数据库迁移（不新增列）。
- 版本号变更，v0.3.4（client 0.3.4 / server 0.3.3）。
