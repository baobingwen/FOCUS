# 0004: 学习标签 — 科目之下的知识点二级细分

学习记录可挂多个标签，实现「科目太粗，想知道今天高数/线代各学了多久」的精细统计与检索。

## Status

**accepted**

## Design

### 核心概念：标签（Tag）

标签与科目、备注是三个不同维度的元数据：

| 维度 | 科目 | 标签 | 备注 |
|------|------|------|------|
| 粒度 | 一级分类（粗） | 二级细分（细） | 自由文本 |
| 数量 | 单条记录 1 个 | 单条记录 0..N 个 | 单条记录 1 段文本 |
| 选择方式 | 单选 | 多选 | 手打 |
| 价值 | 分类 | 精细统计 + 检索 | 描述 |

- **扁平全局标签库**：所有标签是一个扁平的库（高数、线代、真题、错题…），任何科目的记录都能挂任何标签，不做科目→标签的层级耦合。跨科目标签（真题/错题）天然可用。
- **统计时交叉**：按「科目 × 标签」分组即可回答「今天数学里高数学了多久」，不需要数据层强制层级。
- **空库自定义**：标签库初始为空，学习中「+ 标签」新增，建过一次永久保留。知识点高度个人化，不预设。

### 数据模型

新增两张表（迁移 `002_add_tags.sql`）：

```sql
CREATE TABLE tags (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE record_tags (
  record_id INTEGER NOT NULL REFERENCES records(id) ON DELETE CASCADE,
  tag_id   INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (record_id, tag_id)
);

CREATE INDEX idx_record_tags_tag ON record_tags(tag_id);
```

选多对多而非 `records.tags` JSON 列的原因：

| 能力 | 多对多关联表 | JSON 列 |
|------|------------|---------|
| 改标签名全局生效 | ✅ 一条 UPDATE | ❌ 全表扫行改 JSON |
| 删标签清关联 | ✅ 级联删除 | ❌ 全表扫行 |
| 按标签统计 | ✅ SQL JOIN | ❌ 扫全表 |
| 前端拿全量标签库做快捷点选 | ✅ | ❌ |

### 后端 API

| 接口 | 行为 |
|------|------|
| `GET /tags` | 全量标签库（学习中选择器用） |
| `POST /tags` | create-or-get：重名幂等复用（返回已有），不建重复 |
| `DELETE /tags/:id` | 删标签 + 级联清所有记录关联 |
| `POST /records` | 学习模式接受 `tags: string[]`，入库时 create-or-get 并建关联 |
| `GET /records` | 每条记录返回 `tags` 数组 |
| `PATCH /records/:id` | 扩展接受 `tags: string[]`，整组替换关联（历史页编辑）；保留 notes 逻辑 |

- 休息记录无标签概念（同备注）：`POST /records` 的 `tags` 仅在 `mode === 'study'` 时生效。
- 标签仅挂学习记录，`record_tags` 的 `record_id` 指向 records，不校验 mode（由写入侧保证）。

### 前端交互

| 位置 | 行为 |
|------|------|
| **学习中** | 备注上方一排标签 chips：点选 toggle +「+ 标签」新增（从 `GET /tags` 加载全库）；结束保存时随记录提交 |
| **历史页·查看态** | 科目旁显示标签 chips；点标签 = 按它筛选（chip 高亮指示当前筛选）；列表上方有标签筛选行 |
| **历史页·✏️ 编辑态** | 标签带 × 移除 +「+ 标签」新增；备注 + 标签一起 PATCH 保存 |
| **今日概览** | 按科目条形图之外加「按标签分组」时长（纯前端从 records 聚算，零后端改动） |
| **删除** | 学习 chip 与历史 chip 上的 ×，confirm 后级联删除 |

### 统计 / 筛选

- **今日概览按标签分组**：纯前端聚算 —— 历史页本来就拉取了当天全部记录（记录返回带 `tags`），前端按标签累加 `duration_ms` 即可，后端零改动。
- **历史页按标签筛选**：纯前端过滤 —— 点记录上的标签 chip 或列表上方筛选行，只显示含该标签的记录。

### 边界规则

| 规则 | 取值 |
|------|------|
| 名称规范 | trim 去首尾空白、非空才建 |
| 重名 | 幂等复用，不报错、不建重复 |
| 长度上限 | ≤ 12 字，超长拒建 |
| 与科目同名 | 允许（不同维度，统计分组独立不混淆） |
| 单记录标签数 | 不设上限，chips 自然换行 |
| 休息记录 | 无标签区（同备注） |
| 重命名 | v1 不做，删了重建即可 |

## Considered Alternatives

- **`records.tags` JSON 列**：最省事，但改/删标签要全表扫描、统计扫全表、没有全局标签库。统计是本功能核心价值，放弃。
- **层级归属（标签从属科目）**：结构化更强，但标签库变两级树、删科目要级联删标签、统计逻辑锁死层级。代价大、收益仅是「选科后标签自动过滤」的前端效果，不做数据层耦合。
- **结束学习统一打标签**：标签最准但每次结束多一步强制弹窗，违背极简，放弃。改为学习中随时打 + 历史页可补改。

## Consequences

- 「标签」成为学习时段的新元数据维度，需在 CONTEXT.md 中定义。
- 数据库新增 tags + record_tags 两张表（迁移 002）。
- records 的 API 响应与写入扩展 tags 字段。
- 客户端 useTimer 增加 tags 状态、TimerPage 增加标签选择区、HistoryPage 增加标签展示/编辑/筛选、TodayOverview 增加按标签分组。
- 版本号变更，v0.3.0。
