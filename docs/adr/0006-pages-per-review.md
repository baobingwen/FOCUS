# 0006: 每次复习的页数 — 学习记录挂载复习页数

考研备考常以「翻书页数」衡量复习进度。给每条学习记录挂一个可选页数，回答「今天/这个科目复习了多少页」，并把页数随记录永久留存、可回溯可修改。

## Status

**accepted**

## Design

### 数据模型

`records` 表新增 `pages` 列（迁移 `004_add_pages_to_records.sql`）：

```sql
ALTER TABLE records ADD COLUMN pages INTEGER;
```

- **值域**：正整数 1~9999，**选填**（不填为 NULL，旧记录天然兼容）。
- **仅学习记录**：休息记录没有页数概念，无条件忽略该字段（存 NULL）。
- **形式是单个整数，不是页码范围**：范围（如 121-150）能表达位置但无法 SUM 汇总、输入成本高；整数满足「今日 N 页」「科目合计」的统计需求，位置信息交给备注。

### 后端 API

| 端点 | 行为 |
|------|------|
| `POST /records` | `pages` 选填，校验 1~9999 整数（非整数/0/负数/超上限 → 400）；学习模式才存储，休息模式无条件忽略 |
| `PATCH /records/:id` | `pages` 选填，同规则校验；`null` 表示清空；仅学习记录可改（与 notes/tags 同规则） |
| `GET /records/today` | 新增 `total_pages`（今日学习记录 SUM，COALESCE 防 NULL）+ `by_subject[].total_pages`（按科目合计） |

### 前端交互

**学习中**（标签与备注之间，与备注同表单风格）：

- 「页数（选填）」标签 + 数字输入框 + 固定 **+1/+5/+10** 快捷芯片。
- 快捷芯片是复习场景的核心：页数只增不减，边翻边点，比逐个打字快（手机友好）；手动输入用于校正。
- 冻结/暂停态视觉灰化同备注（冻结仅发生在离开页面时，交互不禁用无实际冲突）。
- 结束学习时随记录提交；`startStudy` 清零。

**历史页**：

- 有页数时显示「📖 N 页」徽标（记录行首部），无页数不显示。
- ✏️ 编辑态新增页数输入（`null` = 未填写 → 提交 null 清空），复用 PATCH 接口。

**今日概览**：

- 顶部「📖 今日 N 页」（`total_pages > 0` 才显示）。
- 科目分组行附「· N 页」文字；**条形图仍按时长渲染**——时长看条形、页数看文字，双数据进图会混淆两个语义。

### 快捷芯片固定档位的原因

+1/+5/+10 覆盖绝大多数复习节奏（精读一页页点、快速翻页 +5/+10）。档位可配置需要设置页 + 持久化，为极小需求引入复杂度，不值。

## Considered Alternatives

- **页数写进备注**：零迁移成本，但汇总统计靠文本解析，脆弱且展示混乱。结构化字段才能 SUM。
- **页码范围**：见「数据模型」。
- **开始前预设页数**：预估数与实际复习数通常不符，需要中途改，容易忘。学习中常驻输入与实际进度同步。
- **结束时弹窗填写**：数值新鲜但把「点一下结束」变成两步操作，且与暂停态已有确认弹窗叠加。学习中常驻输入零新增弹窗（v0.3.0 标签同款接入方式）。
- **必填**：会拦截「没翻书的学习」（看视频/刷题），强逼填 0 别扭。选填符合极简哲学。

## Consequences

- `records` 表新增 `pages` 列（迁移 004），旧记录为 NULL，历史页不显示徽标、概览 SUM 忽略。
- 服务端：POST/PATCH 新增 pages 校验；`/today` 新增 `total_pages` 与 `by_subject[].total_pages`。
- 客户端：useTimer 增加 `pages` 状态（清零时机同 notes/tags）；TimerPage 页数区块；HistoryPage 徽标 + 编辑；TodayOverview 汇总文字。
- 版本号变更，v0.3.3（client 0.3.3 / server 0.3.2）。
